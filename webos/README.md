# 漫游有解——多约束动态游览路线规划智能体（v1.0）

从「单场所游览助手」长大的**游览路线规划智能体平台**：行前看懂目的地（内容中心）→ 排好多日行程（行程规划器）→ 预约导游（服务市场）→ 到了现场跟着走、听着逛（游览助手）→ 平台可运营（管理后台）。

**零依赖单仓**：Node.js ≥ 18 即可运行，无需 npm install、数据库或 Redis。

## 启动

```bash
node server/index.js
# 前台（手机优先）: http://localhost:8080
# 管理后台（PC）:   http://localhost:8080/admin.html
```

- 前台导航三个频道：**发现**（目的地门户与路线模板）· **规划**（现场游览助手）· **我的**（历史行程、行程单、偏好）。导游预约市场已下线，订单只保留「保存行程单」。
- 管理令牌来源：环境变量 `ADMIN_TOKEN` > `config.json` 的 `admin.token` > 首次启动自动生成并写入 `data/admin-token.txt`（同时打印在服务器控制台）。
- 端口：`PORT=9000 node server/index.js` 可覆盖。
- 数据：运行时数据在 `data/db.json`；内容库在 `data/content/*.json`（随包分发，可离线浏览）。

## 平台能力总览（v1.0 新增 + 既有）

| 子系统 | 说明 | 依赖 |
| --- | --- | --- |
| **内容中心** | 12 城市 / 47 场所 / 135 条三层讲解（到了看什么 → 简短讲解 → 深入了解，含史实/传说标注与来源）/ 12 篇攻略；四路全局搜索 | 无（随包分发） |
| **城市行程规划器** | 选城市+天数+兴趣+节奏 → 确定性算法按「评分×兴趣权重+地理就近」排出 1-7 天行程，含每日动线、看点、参考票价与预算估算 | 无 |
| **导游市场** | 19 位示例导游档案；按日期加载档期 → 下单 → 模拟支付 → 完成服务 → 评价，订单状态机 + 幂等键 + 档期互斥 | 无 |
| **语音导览** | 讲解卡内置播放器（浏览器语音合成，语速可调，页面明确标注"非真人录音"） | 无 |
| **管理后台** | 数据看板（统计卡 + 7 日趋势图 + 城市热度）、内容管理（五集合增删改，写回 JSON）、订单管理（状态流转 + 手机号脱敏）、用户会话、数据运维 | 管理令牌 |
| **现场游览助手**（v0.3 既有） | 向导式规划、高德实时场所/路网、确认条、三主推荐+备选、到站讲解、现场问答（只依据已核验资料）、途中自然语言调整、游记小结 | 高德 Key + LLM |

**无 Key 也能用**：内容中心（城市/场所/攻略/讲解）与多日行程规划不依赖任何外部服务，开箱即用；「规划」频道的实时路线规划仍按 v0.x 规则要求配置高德 Key（页面给出配置指引，不用虚构数据顶替）。

## 交互设计（前台）

**发现频道**：精选路线模板（按时长/主题筛选，一键带入规划）→ 城市横滑卡片 → 讲解试听 → 多日行程入口 → 攻略与热门场所。城市详情 → 场所详情（看点列表、讲解试听、票价与时间诚实标注）→ 两个出口：生成现场游览路线 / 排进多日行程。

**规划频道**（v0.3 向导式，保持不变）：先选择再规划——①想怎么逛 ②哪个地方 ③怎么安排；AI 是助手不是入口（一句话填好并规划，默认收起）。

**导游预约**：日期 → 档期（示例数据，确定性生成）→ 联系信息 → 模拟支付 → 订单。全程标注「示例档案 / 模拟支付」。

## 智能体编排内核

真实场所（`live:*`）与周边片区（`area_amap`）的规划不再是"规则选点 + 一次求解"，而是一个有反馈闭环的智能体（`server/agent_kernel.js`）：

1. **提名**：大模型按城市/场所、时长、兴趣、终点提名"真正值得去"的具体地点（宁少勿错）；
2. **核实**：每个提名用高德周边/文本检索落到真实 POI，名称 + 步行范围双校验，查不到的直接丢弃（不让模型编造的地点进路线）；
3. **评审**：大模型给候选打值得度、建议停留、纠正分类、识别噪声点（停车场/XR 馆/连锁店…），与高德路网矩阵抓取并行；
4. **求解 + 独立验证**：仍由确定性求解器排线、`verifyRoutePlan` 复核时长/终点/重复路段；
5. **反思修复**：按质量分 Q（值得度、时长利用、兴趣、非商业、末段适配、少重复、提名覆盖）诊断"末段空走 / 时长没用满 / 低价值站 / 漏掉代表性地点 / 过度商业化"，生成纳入/去掉/替换操作重新求解，只接受 Q 确实提升的修改（最多 3 轮）；
6. **解释**：大模型写推荐理由，再做事实校验（数字、地名、末段步行、回头路必须如实），不过关就用诚实模板。

大模型任一步失败/超时都自动回退到规则候选与模板文案，不影响出线。开关：`config.json` 的 `agent` 段（`enabled / llmNominate / llmAppraise / llmCritic / llmExplain / maxRounds`），或环境变量 `AGENT_KERNEL=off`。
自测：`npm run test:agent-kernel`（模拟高德 + 假大模型）；线上对照：`BASE_URL=http://<服务地址> npm run eval:agent`（6 个场景，输出站数、时长利用、末段步行、商业占比、核心点命中、Q、耗时）。

## AI 的边界

- **AI 提建议，求解器与验证器拍板**：一句话 → 结构化需求 → 服务端白名单校验；大模型提名/评审的地点必须经高德核实才进候选池，最终路线由确定性求解器排出并独立复核。
- **资料不足时说没有**：现场问答与讲解都受此约束；无 LLM 时讲解显示"内容暂缺"。
- **如实告知的自动决策**：起点离场所超过 1km 时自动把起点改到场所入口，并明确提示「接近路程不计入游览时长」（§4.3）。

## 数据来源与诚实边界

| 层 | 来源 | 标注 |
| --- | --- | --- |
| 内容库（城市/场所/讲解/攻略/导游） | 随包分发，`data/content/*.json`，公开资料整理 | `library_v1`：未实地核验；票价/时间显示"未核验" |
| 导游档案与档期 | 示例数据（`demo: true`），档期由确定性哈希生成 | UI 恒显「示例」徽章；"非真实排班" |
| 订单支付 | `payment.mode = 'simulated'` | 页面标注"模拟支付，不接真实资金流" |
| 场所搜索/路网/步行路线（规划频道） | 高德 Web 服务 + JS API | 未配置 Key 时明确提示，不虚构兜底 |
| 讲解生成/现场问答 | LLM（OpenAI 兼容） | AI 生成内容标注"未经资料核验" |

- 内容库坐标为近似值（GCJ02），仅侧行程示意；行程中的交通提示为直线距离估算并如实说明。
- 高德返回的 POI/路段按平台许可**不落库**，只存在于当次路线版本中。
- 测试夹具：`server/data/*.json` 仅用于回归测试与数据运维视图，不出现在产品界面。

## 验收自测

```bash
node scripts/acceptance.js              # 全链路验收
npm run test:planner-constraints        # 纯算法：无重复环路、死胡同冲突、Provider 折线重叠
npm run test:route-strategies           # 算法直解 vs 有界智能体编排，同场景对照
```

现场路线默认启用固定硬约束“同一物理路段不重复”：自有路网按稳定 `edgeId` 精确约束；高德路线按约 6 米网格重采样后的折线分段做会话内近似匹配，并明确标注无法证明绝对零重复。死胡同、唯一桥梁或同入口闭环无法满足时返回 `NO_NON_REPEATING_ROUTE`，不会静默发布回头路方案。

路线生成默认使用有界智能体编排（`routePlanningMode: "agent"`）：智能体只编排“约束台账 → 确定性求解 → 独立验证 → 修复提议”，不直接生成道路序列，也不会自动放宽硬约束。遇到死胡同必去且必须回到起点时，会返回需用户确认的“改终点”等提议。可设置环境变量 `ROUTE_PLANNING_MODE=algorithm` 回退到纯算法直解，用于 A/B 测试和故障隔离。

覆盖：起点降级、坐标单次转换、时间窗、追问、无重复路段、诚实约束、幂等、409、回顾，以及内容库、行程、订单和管理后台等能力。

## 管理后台

- 登录：`/admin.html`，输入管理令牌（见上文令牌来源）。生产环境务必配置强令牌并限制来源 IP。
- 看板：用户/行程/订单/收入（模拟）统计、近 7 日趋势（Canvas，无依赖）、城市热度、订单构成。
- 内容管理：城市/场所/讲解/攻略/导游五个集合的增删改，以 JSON 编辑整行，保存即原子写回 `data/content/*.json` 并重载内存索引。
- 订单管理：全部订单、状态流转（受状态机约束）、联系人手机号脱敏。
- 数据运维：`data/db.json` 各集合只读浏览。

## 打包与部署

> 完整部署、启动、运维与排错说明见 **[部署与启动指南.md](./部署与启动指南.md)**；`deploy/` 提供 systemd、pm2、Docker、Nginx 配置模板。

- 依赖：仅需 **Node.js ≥ 18**。常驻用进程守护拉起 `node server/index.js`；反向代理需支持 SSE（关闭缓冲、放宽读超时）。
- 安全：`config.json` 含密钥与管理令牌，**不要提交到代码仓库或对外分发**。

## 已知边界（与文档一致的诚实声明）

- 内容库 v1 为公开资料整理：**未实地核验**，票价/开放时间/交通均以官方公示与现场为准；这是产品持续运营的内容采集任务（对应文档 S0）。
- 高德地图服务为**规划频道的必需项**：未配置时实时路线规划不可用（页面给出配置指引），内容/行程/市场不受影响。
- 导游为示例档案、档期为示例数据、支付为模拟：接入真实从业者需补充资质审核与合规流程（见部署指南 7 节）。
- ASR/TTS 未接入：讲解播报用浏览器语音（页面有标注）；语音输入回退文本框。
- 高德个人开发者配额：步行规划约 3 QPS，代码内置限速与调用预算；企业级用量请升级账号。
- Web 版游览助手定位为**前台应用**：锁屏/切后台不保证持续采样与播报（§12.5）。
