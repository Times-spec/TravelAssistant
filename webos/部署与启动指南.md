## 3. 配置

### 3.1 配置文件与环境变量

配置读取顺序：**环境变量 > `config.json` > 内置默认值**。环境变量名：

| 环境变量 | 对应配置 | 说明 |
| --- | --- | --- |
| `PORT` | `port` | 监听端口，默认 8080 |
| `AMAP_JS_KEY` | `amap.jsKey` | 高德 Web 端（JS API）Key |
| `AMAP_JS_SECRET` | `amap.jsSecurityCode` | 高德 JS 安全密钥 |
| `AMAP_WS_KEY` | `amap.webServiceKey` | 高德 Web 服务 Key（服务端用，**绝不下发到浏览器**） |
| `LLM_BASE_URL` | `llm.baseUrl` | OpenAI 兼容接口地址 |
| `LLM_API_KEY` | `llm.apiKey` | LLM 密钥 |
| `LLM_MODEL` | `llm.model` | 模型名，如 `deepseek-chat` |

生产环境推荐用环境变量注入密钥，`config.json` 里留空，避免配置文件被误拷：

```bash
export AMAP_WS_KEY=xxx AMAP_JS_KEY=xxx AMAP_JS_SECRET=xxx
export LLM_BASE_URL=https://api.deepseek.com/v1 LLM_API_KEY=xxx LLM_MODEL=deepseek-chat
node server/index.js
```

### 3.2 模式判定（关键）

| Provider | 触发条件 | 缺失时的行为 |
| --- | --- | --- |
| 地图（**必需**） | 配了 `amap.webServiceKey` → `amap` | 未配置：服务能启动但**规划功能不可用**，首页显示配置指引；不做虚构数据兜底 |
| LLM | 配了 `llm.baseUrl` + `llm.apiKey` → `http` | 自然语言理解回退规则引擎（能力弱一些）；真实点位讲解显示“内容暂缺”而非编造 |
| ASR/TTS | 配了对应地址与 Key → `http` | 语音输入回退文本框；讲解播报使用浏览器自带语音（页面上有说明） |

### 3.4 数据来源与如实标注（产品行为，不是免责声明）

- 场所（公园/景区/校园）、场内点位、步行路线、逆地理、坐标转换 **全部来自高德实时检索**；
- 场所覆盖分母写作「高德在园内检索到的 N 个点位（非园区完整清单）」，不承诺“逛完全园”；
- 高德不提供营业时间与票价 → 校验层标记 `unknown`，方案状态为**条件性方案**并提示“出发前现场确认”；
- 无资料点位的讲解由 LLM 生成并标注**“AI 生成，未经资料核验”**；
- 高德返回的 POI 与路段按平台许可**不落库**（`data/db.json` 里只有路线版本与行程记录）；
- `server/data/*.json` 是内部**测试夹具**，仅供自动化回归测试，不出现在产品界面。

### 3.3 限流与预算（`limits`）

```json
"limits": { "maxPoiCandidates": 24, "maxRoutingCalls": 60, "maxLlmTokens": 4000, "maxWallTimeSec": 45 }
```

高德个人开发者账号步行规划约 **3 QPS**，代码内置 380ms 调用间隔 + 指数退避重试；若升级到企业账号，可调小间隔（`server/amap.js` 中 `setTimeout` 值）。

## 4. 启动方式

### 4.1 本地 / 内网直接启动

```bash
node server/index.js                      # 前台，默认 8080
PORT=9000 node server/index.js             # 换端口
nohup node server/index.js > app.log 2>&1 &   # Linux/macOS 后台运行
```

Windows 上想后台常驻，用「任务计划程序」新建任务：程序 `node.exe`，参数 `server/index.js`，起始位置填项目目录，触发器选「系统启动时」。

**验证启动成功**

```bash
curl -s http://localhost:8080/v1/config
# 期望返回 {"demoMode":false,"providers":{"map":"amap","llm":"http",...}}
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/
# 期望 200
```

### 4.2 生产常驻（Linux systemd）

```bash
sudo cp deploy/smart-tour.service /etc/systemd/system/
sudo vim /etc/systemd/system/smart-tour.service   # 按注释改 WorkingDirectory / User / PORT
sudo systemctl daemon-reload
sudo systemctl enable --now smart-tour
systemctl status smart-tour        # 查看状态
journalctl -u smart-tour -f        # 实时日志
```

常用运维命令：

```bash
sudo systemctl restart smart-tour   # 改完配置后重启
sudo systemctl stop smart-tour
```

### 4.3 生产常驻（pm2，跨平台）

```bash
npm i -g pm2                                   # 唯一需要安装的全局包，可选方案
pm2 start deploy/ecosystem.config.js
pm2 save && pm2 startup                        # 开机自启
pm2 logs smart-tour                            # 看日志
pm2 restart smart-tour                         # 重启
```

> 不改动全局环境也可以不用 pm2：用 systemd（Linux）或任务计划（Windows）即可。

### 4.4 Docker

```bash
docker build -t smart-tour:0.1.0 -f deploy/Dockerfile .
docker run -d --name smart-tour -p 8080:8080 \
  -e AMAP_WS_KEY=你的服务端Key -e AMAP_JS_KEY=你的JSKey -e AMAP_JS_SECRET=你的安全密钥 \
  -e LLM_BASE_URL=https://api.deepseek.com/v1 -e LLM_API_KEY=你的LLMKey -e LLM_MODEL=deepseek-chat \
  -v $(pwd)/data:/app/data \
  smart-tour:0.1.0
```

或用 compose：`docker compose -f deploy/docker-compose.yml up -d`

数据卷 `-v .../data:/app/data` 必须挂载，否则容器重建会丢行程记录。

> ⚠️ Dockerfile 与 compose 文件按标准写法提供，本机未安装 Docker，**未做构建实测**；其余启动方式均已实测。

### 4.5 反向代理 + HTTPS（真机户外测试必需）

浏览器定位要求**安全上下文**：局域网 HTTP 地址在手机上无法定位（地图与规划仍可用）。生产环境用 Nginx 终止 TLS：

```bash
sudo cp deploy/nginx.conf.example /etc/nginx/conf.d/smart-tour.conf
# 改 server_name 与证书路径后
sudo nginx -t && sudo systemctl reload nginx
```

SSE 相关的三个关键配置（已在示例文件中写好，**别删**）：`proxy_buffering off`、`proxy_read_timeout` 放宽、`X-Accel-Buffering no`。缺任何一个都会导致规划进度卡住不更新。

### 4.6 Android 客户端（APK）

Web 端已封装为原生 Android 应用（WebView 壳 + 原生定位/权限/服务器配置）：

```bash
# 安装包（已签名）
dist/android/smart-tour-0.1.0-release.apk     # 正式版 39KB
dist/android/smart-tour-0.1.0-debug.apk       # 调试版（带 WebView 远程调试）

# 重新构建
export JAVA_HOME="C:/Program Files/Eclipse Adoptium/jdk-17.0.16.8-hotspot"
cd android && ./gradlew assembleDebug assembleRelease
```

- **首次使用**：先启动服务端，再在 App 的「连接服务端」页填 `http://<电脑局域网IP>:8080`
  （模拟器用 `http://10.0.2.2:8080`），点「测试连接并保存」即可。右上角 ⚙ 可随时改地址。
- 定位：Android WebView 在局域网 HTTP 下不支持 `navigator.geolocation`，APK 用**原生定位桥**
  补齐（返回 WGS84，服务端统一转 GCJ02），与 Web 端行为一致。
- 验收：`node scripts/apk-probe.js`（需 debug 包 + `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`），
  14 项全绿：原生定位、一句话规划、高德底图、会话持久化。
- 详细说明见 `android/README.md`（权限、签名、明文 HTTP 风险、已知限制）。

## 6. 数据与备份

| 文件 | 内容 | 处理建议 |
| --- | --- | --- |
| `data/db.json` | 会话、需求、路线版本、任务事件、行程与反馈 | **必须备份**；直接拷贝即迁移 |
| `config.json` | 配置与密钥 | 备份但勿外发 |
| `server/data/*.json` | 内部测试夹具 | 随代码走，可版本管理 |

```bash
cp data/db.json backups/db-$(date +%F).json      # 备份
rm data/db.json && node server/index.js          # 清库重来（自动重建空库）
```

> 注意：清库会让所有客户端旧会话立即失效（新版客户端会自动重建会话，用户无感）。
> 验收脚本用 `DATA_DIR` 指向独立目录，切勿在生产服务运行时删除 `data/db.json`。

注意事项：
- 单实例假设：JSON 文件存储不支持多进程并发写；需要横向扩展时改接 PostgreSQL（表结构已按 §15 对齐）。
- 高德返回的 POI/路段按许可**不落库**，只存在于当次任务的路线版本中；自有场所包（测试夹具/未来实地采集包）可长期保存。
- 删除权限：行程删除接口会同时清理关联反馈与偏好证据；共享的场所包不受影响。

## 7. 日志与错误码

日志输出到 stdout（`journalctl -u smart-tour` / `pm2 logs` / `app.log`）。

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `PROVIDER_RATE_LIMITED` | 高德/LLM 限流 | 自动退避重试 2 次；持续出现说明配额耗尽，控制台查配额 |
| `PROVIDER_ERROR` | Key 无效或权限不足 | 核对该 Key 的服务类型（Web 服务 vs Web 端）与白名单 |
| `NO_FEASIBLE_ROUTE` | 硬约束下无可行解 | 前端会给出可调整项，属正常业务结果 |
| `ROUTE_VERSION_CONFLICT` | 重排基准版本已过期 | 前端自动刷新，属正常并发保护 |
| `CRS_UNSUPPORTED` | 坐标系不支持 | 只会出现 `WGS84`/`GCJ02` 两种 |
| `SPEECH_UNAVAILABLE` / `TTS_UNAVAILABLE` | 语音服务未配置 | 用文本框输入、文本阅读或浏览器语音 |

## 9. 故障排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `EADDRINUSE: address already in use :::8080` | 端口被占用 | `PORT=9000 node server/index.js` 或结束占用进程 |
| 页面能开但一片空白 | 静态资源路径/JS 报错 | F12 看 Console；确认 `web/` 目录完整 |
| 手机打不开局域网地址 | 防火墙/不在同一网段 | 放行端口、关闭客户端隔离；真机定位另需 HTTPS |
| 定位一直失败 | 非 HTTPS / 权限被拒 / 室内信号差 | 用 HTTPS 域名；或改用搜索、地图选点 |
| 地图区域空白（真实路线） | 高德 JS Key 或安全密钥不对 | 核对 `jsKey` 与服务类型；F12 看 `webapi.amap.com` 请求 |
| 规划进度一直转圈 | 反代把 SSE 缓冲了 | 按 §4.5 三个 SSE 配置项改 Nginx |
| 高德报 `USERKEY_PLAT_NOMATCH` | Key 服务类型不匹配 | Web 服务 Key 用于服务端，Web 端 Key 用于浏览器，别混用 |
| `CUQPS_HAS_EXCEEDED_THE_LIMIT` | QPS 超限 | 代码已限速；并发多人同时规划时升级账号或加大间隔 |
| LLM 401/超时 | Key 错或网络不通 | 直接 curl 接口验证；失败会自动回退规则引擎，不阻塞规划 |
| 改了 `config.json` 没生效 | 服务未重启 | 重启进程（配置只在启动时读取） |
| 讲解显示"内容暂缺" | 真实点位无资料且未配 LLM | 配置 LLM 后会生成并标注"AI 生成未核验" |
| 首页提示"未配置地图服务" | 缺少 `amap.webServiceKey` | 按提示填 Key 或设环境变量后重启（地图是本产品的必需依赖） |
| 出现"会话已失效，请重新建立会话" | 旧凭证对应的服务端会话已不存在（服务端清库/迁移/换机后必然如此） | **已自愈**：客户端收到 401 会自动重建访客会话并重试一次；若反复出现说明服务端不可达或 `/v1/sessions/guest` 被阻断 |
| 夜间规划提示"园内点位均已关闭" | 该场所当前时段不在开放窗口内 | 属预期结果，页面会给出一键「改到明早 09:00 出发」或「改成周边随便逛逛」 |
| 搜索不到某个公园 | 名称不匹配或不在该城市 | 换关键词或补城市参数；系统只收录高德类型为公园/景区/校园的结果 |
| 路线都是"条件性方案" | 真实场所的营业时间与票价未经核验 | 这是如实标注；实地采集核验（文档 S0）后可升级为已核验方案 |

## 10. 安全清单

1. **服务端密钥只放服务端**：`amap.webServiceKey`、`llm.apiKey`、ASR/TTS 密钥绝不出现在前端；只有 `amap.jsKey` 与安全密钥按高德设计可以进浏览器。
2. `config.json` 加入 `.gitignore`，`with-keys` 分发包不外发。
3. 反向代理只暴露 80/443，应用端口不对公网开放。
4. 权限校验：所有行程/计划接口按会话身份校验归属，知道 ID 也无法访问他人数据。
5. 外部链接抓取：讲解资料管线对外部 URL 做内网地址阻断（未配置 LLM 检索时不启用），避免服务端被诱导访问内网。
6. 用户数据最小化：默认不保存原始音频与连续轨迹；删除行程会清理关联个人信息。
7. 日志脱敏：上线时不要把完整 Key 打进日志。

## 9. 平台运维补充（v1.0）

### 9.1 管理后台

- 入口：`http://<host>:8080/admin.html`（PC 浏览器使用）。
- 管理令牌来源优先级：环境变量 `ADMIN_TOKEN` > `config.json` 的 `admin.token` > 首次启动自动生成并写入 `data/admin-token.txt`（令牌同时打印在服务器控制台）。
- **生产环境必须**：在 `config.json` 配置强令牌（≥ 24 位随机串），并通过 Nginx 限制 `/admin.html` 与 `/v1/admin/*` 的来源 IP：

```nginx
location /admin.html { allow 10.0.0.0/8; deny all; proxy_pass http://127.0.0.1:8080; }
location /v1/admin/  { allow 10.0.0.0/8; deny all; proxy_pass http://127.0.0.1:8080; }
```

- 能力：数据看板（统计/趋势/城市热度）、内容管理（城市/场所/讲解/攻略/导游增删改，保存即写回 `data/content/*.json`）、订单管理（状态流转、手机号脱敏）、用户会话、数据运维（`data/db.json` 只读浏览）。

### 9.2 内容库

- 位置：`data/content/{cities,venues,narrations,articles,guides}.json`，随包分发，**不依赖任何 Key**。
- 标注：全部内容 `reviewStatus: library_v1`（公开资料整理，未实地核验）；讲解内 `legend: true` 的 claims 为传说；票价/开放时间未核验项在界面显示"未核验"。
- 修改方式：管理后台编辑（推荐，自动原子写回 + 重载索引），或直接改 JSON 后在管理后台点「重载」（或重启服务）。
- 备份：内容文件与 `data/db.json` 一起纳入备份即可。

### 9.3 导游市场与订单

- 导游为**示例档案**（`demo: true`），档期由确定性哈希生成（同 guide+date 恒定，可回归测试），**非真实排班**。
- 支付为 `simulated`：`POST /v1/orders/{id}/pay` 只改状态与生成模拟流水号，不接任何真实资金流。接入真实支付前需补充：资质审核、实名、支付渠道、发票与退改规则。
- 订单状态机：`created → paid → finished`，任意态可 `cancelled`（已支付生成模拟退款记录）；服务端校验不可跳级，前端与管理后台共用同一状态机。
